# CLAUDE.md – Entegris A300 Shell Assembly HMI

Context for Claude Code. Read this before changing code.

## Project
- WPF HMI (C#, .NET Framework 4.8) for the **Entegris A300 Shell Assembly machine** (assembles FOUP shells: handles, conveyor plate, side columns screwed by FIAM torque driver + UR robot).
- Repo: `PENTAPQBU2/Entegris-A300`, solution `HMI_Master_KX7500.sln`, project `HMI_Master_KX7500` (exe: `HMI_SSDC_PIM.exe`), version 1.3.13.0 (= production).
- PLC: **Keyence KV** (KV STUDIO), accessed through `CommunicationProtocols/KeyenceDll.cs` (KV COM+ Library, `DBCommManager`).
- Libraries: `Libraries/Pentamaster.dll` (login / user accounts, MdbTool), `PQ.HMI.dll` (XmlTools). Both identical to production.

## Build & run
- **Always build `Debug | x86`** (Jet OLEDB 4.0 and Pentamaster.dll are 32-bit).
- `#if DEBUG` → data folder `C:\HMI_A300\…`, FOUP CSV `D:\HMI_A300\FOUP CSV\`.
- Release (machine PC) → `C:\HMI\…`, FOUP CSV `D:\HMI\FOUP CSV\`.
- Machine data (`MachineConfiguration\*.xml`, `MachineSettings\*.mdb`) comes from machine backup; normal user must have write access to `C:\HMI_A300`.
- Login: `penta` / `#penta123` (Pentamaster level), stored in `MachineSettings\UserAccountSetting.mdb`.
- No PLC on dev PC → **offline mode** (see below). PLC reads return ""/0/false, writes do nothing.

## Offline mode – DEV PC ONLY, NEVER COMMIT
Marked with `// OFFLINE MODE` (search for it). Documented in `OFFLINE_MODE_CHANGES.md`.
- `CommunicationProtocols/KeyenceDll.cs`: `IsOffline` flag, skip KV COM+ calls.
- `Modules/Frame/FrameView.xaml.cs`: in `initializeNonAsync()` folders/log/file paths are initialized **before** `Entergris_TcpCommService` when offline; `isOfflineMode()`; MessageBox of startup exception when offline.
- When committing, stage only the feature hunks, never the OFFLINE MODE hunks.
- Production code must not reference `KeyenceDll.IsOffline` (it only exists in the offline patch).

## Rules
- Keep production behaviour unchanged unless the task says otherwise. Ask before touching lot handling. Since MT_001 the New Lot button writes `EM4250` Shell_Colour_ID and then sets `MR49501` New Lot bit (PLC: rising edge → `MOV.D Shell_Colour_ID W0102`, also turns on `MR49500` New_Lot_Created → lot OEE/UPH start running).
- Keep files UTF-8 **with BOM** and **CRLF** line endings.
- Add new PLC addresses as constants in `Globals/PLCTag.cs`.
- Do not use FOUP barcode `EM3050` – nothing in PLC writes it.

## Torque data / FOUP CSV (MT_003) – `Modules/Frame/FrameView.xaml.cs`
- FIAM torque driver → serial COM6 (`COMPort_Settings_File.xml`) → `SerialListener` → `LoadCellListener()` (assembles message until it ends with `end`/`error`) → `Info()` parses → `foupCsvWriteRow()`.
- Region `FOUP CSV (MT_003)`:
  - Shell start = rising edge `MR4507`/`MR4508` (polled in `Update()` via `foupCsvTrackShell()`, Release only). Pass = `MR49600` seen. End = falling edge → Fail if no Pass.
  - FOUP ID = `<LotID>_<00001>` running number per lot generated by HMI (`MachineConfiguration\FoupCsvRunningNumber.txt` = `lot|number|lastFolder|lastCsv`), resets to 1 on new Lot ID. Rework continues the last FOUP of the same lot (same folder + CSV, rows appended, header rewritten with new result). 1 shell = 1 CSV: HMI restart during a shell continues its `_InProgress` CSV. NOK → PLC pop-up Retry (same shell, same CSV) / Remove (step 360, shell ends without Overall_Pass → `_Fail`).
  - Folder `D:\HMI\FOUP CSV\<LotID>_<00001>_InProgress` → renamed `_Pass` / `_Fail`; file `<yyyyMMddHHmmss>.csv`.
  - File: header block exactly as customer example (`FOUPBarcode`, `LotID`, `Recipe` = shell colour, `Result` 0=Pass/1=Fail; shell type only in COMPort log), blank line, table `,Result,ScrewDateTime,Torque,TargetTorque,TorqueUnit,Angle,Time,ScrewType,Error`, rows `Screw No N,...`.
  - Screws outside a shell → `D:\HMI\FOUP CSV\NoShell\`.
  - DEBUG build simulates shells (screw 1 start, 21 pass). Hidden Test button `btnTest_Click` in `FrameView.xaml` (set Visibility to Visible to test).
- Do **not** split by screw number – production history shows reworks restart at screw 9/18 and NOK retries restart at 1.
