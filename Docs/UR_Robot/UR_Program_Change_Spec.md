# UR Robot Program Change Spec – A300 Shell Assembly (HMI V1.4.0.0)

For: the engineer who edits the UR program on the teach pendant, and the PLC engineer.
Program: `A300 Shell 05092022.urp` + `default.installation` (PolyScope 5.12.1, e-Series).
Purpose: MT_001 recipes EBM, PC Clear, PC Amber, PC Red, PC Green, each with its own robot points.

MT_002 (HMI Robot page) is cancelled. Points are taught on the pendant, the same way as today.
The earlier design (HMI-taught general variables) is kept in `Archive/MT_002_RobotPage/`.

## 1. How the recipe reaches the robot

1. Operator selects the recipe on Lot Entry and presses New Lot.
2. HMI writes the recipe ID (EM1559), recipe name (EM1623) and the recipe's **robot point set**
   number to the new address `HMI_Robot_PointSet` **EM4250** (2W, EM4250–EM4251).
3. PLC moves EM4250 to W0102 (`shell_int`, robot int input 1).
4. Robot program builds `screwHeightList` / `screwEntryList` from that point set with
   `rcp_height(shell_int)` / `rcp_entry(shell_int)` (from `recipe_points.script`, generated by the HMI).

The recipe ID and the point set are separate numbers, so recipe IDs can grow (copies get 6, 7 …)
and two recipes can share one point set. The point set of each recipe is set on the HMI Recipe page.

| Recipe (HMI default) | Robot point set = `shell_int` | Robot waypoints |
|---|---|---|
| EBM | 0 | `Point_*b` (today's black, unchanged) |
| PC Clear | 1 | `Point_t*` (today's transparent, unchanged) |
| PC Amber | 2 | `Amb_P01 … Amb_P33` (new, created by the HMI) |
| PC Red | 3 | `Red_P01 … Red_P33` (new, created by the HMI) |
| PC Green | 4 | `Grn_P01 … Grn_P33` (new, created by the HMI) |

Point numbering (same for every set, matches the HMI photo): P1–P21 = screw 1–21,
P22–P33 = entry above screw 1, 2, 3, 7, 8, 10, 16, 17, 18, 19, 20, 21. The other screws enter at the
screw point.

## 2. PLC change

1. New label `HMI_Robot_PointSet`, 2W signed integer, **EM4250**.
2. New rung: `MOV.D EM4250 → W0102`, always on (e.g. contact CR2002). The HMI writes EM4250 only at
   New Lot, so W0102 changes only then.
3. Rungs 057/058 (Shell_Colour_Black / _Transparent → W0102) are no longer triggered: the HMI does not
   set MR4500/MR4501 any more. Delete or disable them so only one rung writes W0102.
4. After a PLC restart EM4250 keeps its value if EM is latched; otherwise the robot gets 0 (black)
   until the next New Lot. Check the EM latch setting.

## 3. Robot program change

### 3.1 Before you start

1. Back up `A300 Shell 05092022.urp`, `default.installation`, `default.variables` to USB.
2. Save the edited program under a new name, e.g. `A300_Shell_V1_4.urp`; make it the default
   program only after the test in section 4 passes.
3. Edit with the robot's own PolyScope (5.12). A file saved by a newer URSim (e.g. 5.26) may not
   load on the robot.

### 3.2 One-time change (tested in URSim 5.26)

1. Copy `recipe_points.script` (from the HMI, section 3.3) into the robot's programs folder.
2. **BeforeStart**, first line: Advanced → **Script**, mode **File**, select `recipe_points.script`.
   (PolyScope 5 has no installation-wide script, so the file is loaded by the program.)
3. **Main_PLC**, above `Switch shell_int`: two **Assignment** nodes
   - `screwHeightList` := `rcp_height(shell_int)`
   - `screwEntryList` := `rcp_entry(shell_int)`

   Type `rcp_height(` on the keyboard (own functions are not in the Function list), then insert
   `shell_int` from the **Input** drop-down. Typed by hand, `shell_int` gives the compile error
   "name 'shell_int' is not defined". `read_input_integer_register(1)` also works.
4. **Suppress** `Switch shell_int` (keep it until the new program is accepted, then delete it).
5. Save the program.

The screw sequence itself is not changed: it still moves to `screwEntryList[ScrewNum]` and
`screwHeightList[ScrewNum]`.

### 3.3 Each new shell type (no program edit)

1. Copy `default.installation` from the robot's programs folder to a USB stick.
2. HMI → **Recipe** page → **Robot point sets**: select the file, the set to copy from, the new set
   number, a name and a pendant prefix (e.g. `Amb`), then **Create point set**. The HMI
   - keeps a copy of the file in `<HMI folder>\RobotBackup\`,
   - adds `Amb_P01 … Amb_P33` (copies of the chosen set, "Variable" ticked) to the file in one block,
   - writes `recipe_points.script` next to it with the lists of every point set.
3. Copy both files back to the robot's programs folder. Load the installation, then the program
   (so the Script node reads the new file).
4. Teach `Amb_P01 … Amb_P33`: Installation → Features → point → Edit / Move here, jog, set the
   point. Save the installation.
5. HMI Recipe page: give the recipe point set number 2. Test one shell at low speed.

`recipe_points.script` only contains sets whose 33 points are all in the installation, so a missing
point cannot stop the program from compiling. An unknown `shell_int` shows "Unknown robot point
set n" and halts the program.

Notes on the existing sets:

- Set 1 (PC Clear) uses the **black** `Point_10bEntry` for screw 10, as `Case 1` does today. Check
  whether that is wanted; if not, create a new set for PC Clear and teach its own point.
- The old point names (`Point_1b`, `Point_t1e` …) can stay. They can be renamed to `EBM_P01 …`
  later; the HMI file `MachineSettings\RobotPointSets.xml` then needs the same names.

## 4. Test (reduced speed, doors closed)

For each recipe: New Lot on the HMI → check W0102 in KV Studio → run one shell at low speed
and check every screw and entry position → then full speed.
