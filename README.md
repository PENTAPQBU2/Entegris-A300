# Entegris A300 Shell Assembly HMI

WPF HMI (C#, .NET Framework 4.8) for the Entegris A300 Shell Assembly machine (FOUP shells screwed by FIAM torque driver + UR robot, Keyence KV PLC).

- Solution `HMI_Master_KX7500.sln`, exe `HMI_SSDC_PIM.exe`
- Build **Debug | x86** or **Release | x86** (Jet OLEDB 4.0 and `Pentamaster.dll` are 32-bit)
- Release uses `C:\HMI\...` and FOUP CSV `D:\HMI\FOUP CSV\`, Debug uses `C:\HMI_A300\...` and `D:\HMI_A300\FOUP CSV\`

## What was changed

### MT_001 – Recipe page
- New Recipe page: create, edit, delete recipes (`MachineConfiguration\ShellRecipe.xml`). Recipe ID 0 = Black, 1 = Transparent, then Amber 2, Green 3, Red 4, Blue 5 (same order as the PLC shell colour index).
- New Lot writes the recipe ID to `EM4250` Shell_Colour_ID and then sets `MR49501` New Lot bit. The PLC copies it to `W0102` (robot `shell_int`).
- Each recipe has a **Robot Point Prefix** (1–5 letters/numbers, starts with a letter, unique). Black and Transparent have no prefix and use the existing robot points.
- **Create Points** (`Service/ShellRecipe/RobotPointService.cs`):
  - Reads an installation file copied from the robot (PolyScope `*.installation`).
  - Adds a copy of the 33 Black points under the prefix: `Point_1b..Point_21b` → `<prefix>_P01..P21`, the 12 entry points `Point_NbEntry` (screws 1, 2, 3, 7, 8, 10, 16–21) → `<prefix>_P22..P33`.
  - Existing points are never changed; points that already exist are kept.
  - Saves `<yyyyMMddHHmmss>.installation` and `recipe_points.script` in the same folder. The script has `rcp_height(n)` / `rcp_entry(n)` that return the point list of recipe ID `n` (index = screw number).
- Tested offline on the dev PC: Amber/Green/Red/Blue created, poses identical to Black, rest of the installation file unchanged. **Not yet tested on the robot.**

#### How to add a new recipe with robot points (example Yellow)
1. Export the latest `.installation` from the robot (always the latest, otherwise recipes added later are missing from the script).
2. Recipe page: add recipe **Yellow**, fill in Robot Point Prefix **Yel**, press **Save**.
3. Select Yellow, press **Create Points**, choose the installation file from step 1, save the new file.
4. Load the new `.installation` on the robot and copy `recipe_points.script` to the robot.
5. Teach `Yel_P01..Yel_P33` on the teach pendant (they start as a copy of Black) and save the installation on the robot.

Robot program (`A300 Shell 05092022.urp`) must still include `recipe_points.script` and use `rcp_height(shell_int)[ScrewNum]` / `rcp_entry(shell_int)[ScrewNum]` – robot engineer.

### MT_003 – FOUP CSV (torque data per shell)
- FIAM torque data (serial COM6) is written to one CSV per shell.
- Shell start = `MR4507` New_Shell / `MR4508` Rework_Shell rising edge, Pass = `MR49600` Overall_Pass, shell end without Pass = Fail.
- FOUP ID = `<LotID>_<00001>` running number per lot (generated by the HMI, because nothing in the PLC writes the barcode `EM3050`). Rework continues the CSV of the last FOUP of the same lot.
- Folder `D:\HMI\FOUP CSV\<LotID>_<00001>_InProgress` → renamed `_Pass` / `_Fail`, file `<yyyyMMddHHmmss>.csv`, header and table as the customer example. Screws outside a shell go to `D:\HMI\FOUP CSV\NoShell\`.
- Lot ID was empty in the old code (read with length 0) – fixed, now read with length 50.

### Lot Entry
- Lot ID, Operator, Quantity, Recipe and the New Lot button are locked while `MR49500` New_Lot_Created is ON; the running lot data is read back from the PLC. Unlock = End Lot.

## Deploy to the machine
1. Back up `C:\HMI` on the machine PC.
2. Build **Release | x86**, copy the output to the machine.
3. Copy the updated `Alarm.mdb` (MT_009) to `C:\HMI\MachineSettings\`.
4. Test: New Lot / End Lot, one shell Pass + one Fail → check `D:\HMI\FOUP CSV\`, Recipe page and Create Points with the robot installation file.
